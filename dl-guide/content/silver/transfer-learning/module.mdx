# Transfer learning with ResNet-18

## Historical question and bottleneck

[How transferable are features in deep neural networks?](https://arxiv.org/abs/1411.1792) (Yosinski et al., 2014) is the primary reference. The original question motivating this module is how to fit a small licensed image subset with frozen and fine-tuned pretrained ResNet-18; document weight provenance. The practical bottleneck for this exercise is explicit: Record ResNet-18 checkpoint license hash preprocessing and frozen parameters. This is a reduced teaching adaptation, not a claim that the paper used our dataset or compute budget.

## Mechanism and equations

$$
\begin{aligned}
h=f_\phi(x),\quad z=Wh+b,\\ \nabla_\phi L=0\quad\text{during frozen-backbone training}
\end{aligned}
$$

Here f is the pretrained backbone with parameters phi, x an input, h its features, z class logits, and W/b the new head. The zero gradient is an explicit freeze, not a mathematical property of the composition; fine-tuning unfreezes selected backbone parameters.

Derive each tensor's dimensions before implementing the equation. State the normalization axis, numerical stabilizer and train/evaluation behavior. Distinguish a mathematical mechanism from the full original training system.

## Implementation notes

Input/task: **small-image-subset**. Output: **Image -> class logits**. Optimize or report **accuracy** in the **maximize** direction. Record ResNet-18 checkpoint license hash preprocessing and frozen parameters.

This is a draft skeleton: reference training and task-specific tests are not implemented. The explicit stub must not be mistaken for a finished model.

## Controlled experiment

Compare scratch frozen-backbone and full-finetuning runs with the same split. Keep split, seed, optimizer schedule and training budget fixed unless that factor is the experimental variable. Report raw quality, wall time and parameter count, not an unsupported superiority claim.

## Pitfalls and checks

- Record ResNet-18 checkpoint license hash preprocessing and frozen parameters.
- Never fit statistics on validation labels or mix held-out examples into training.
- Check shape and finite outputs before interpreting quality; an unrelated baseline cannot satisfy the intended mechanism.
- Draft targets and safety limits have not been GPU-calibrated. No pass threshold is advertised.
