# LSTM and GRU

## Historical question and bottleneck

[Long Short-Term Memory](https://doi.org/10.1162/neco.1997.9.8.1735) (Hochreiter and Schmidhuber, 1997) is the primary reference. The original question motivating this module is how to implement recurrent gates and compare LSTM and GRU TinyShakespeare bits per character. The practical bottleneck for this exercise is explicit: Reset/detach recurrent state at declared boundaries; GRU paper is a separate citation. This is a reduced teaching adaptation, not a claim that the paper used our dataset or compute budget.

## Mechanism and equations

`c_t=f_t*c_prev+i_t*tanh(candidate); h_t=o_t*tanh(c_t). GRU instead mixes old and candidate states through update gates.`

Derive each tensor's dimensions before implementing the equation. State the normalization axis, numerical stabilizer and train/evaluation behavior. Distinguish a mathematical mechanism from the full original training system.

Input/task: **tinyshakespeare**. Output: **[N,T] tokens -> [N,T,V] logits**. Optimize or report **bpc** in the **minimize** direction. Reset/detach recurrent state at declared boundaries; GRU paper is a separate citation.
