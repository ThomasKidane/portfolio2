# INT8 and four-bit quantization

## Historical question and bottleneck

[LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale](https://arxiv.org/abs/2208.07339) (Dettmers et al., 2022) is the primary reference. The original question motivating this module is how to implement calibrated integer quantization and a documented four-bit extension; audit scale zero-point error and memory. The practical bottleneck for this exercise is explicit: Saturation rounding zero points and per-group scale storage included in memory. This is a reduced teaching adaptation, not a claim that the paper used our dataset or compute budget.

## Mechanism and equations

`q=clip(round(x/scale)+zero_point,qmin,qmax); x_hat=scale*(q-zero_point).`

Derive each tensor's dimensions before implementing the equation. State the normalization axis, numerical stabilizer and train/evaluation behavior. Distinguish a mathematical mechanism from the full original training system.

## Implementation notes

Input/task: **quantization-fixture**. Output: **Quantized linear input -> dequantized output**. Optimize or report **relative_output_error** in the **minimize** direction. Saturation rounding zero points and per-group scale storage included in memory.

This is a draft skeleton: reference training and task-specific tests are not implemented. The explicit stub must not be mistaken for a finished model.

## Controlled experiment

Compare per-tensor per-channel and grouped scales on fixed calibration examples. Keep split, seed, optimizer schedule and training budget fixed unless that factor is the experimental variable. Report raw quality, wall time and parameter count, not an unsupported superiority claim.

## Pitfalls and checks

- Saturation rounding zero points and per-group scale storage included in memory.
- Never fit statistics on validation labels or mix held-out examples into training.
- Check shape and finite outputs before interpreting quality; an unrelated baseline cannot satisfy the intended mechanism.
