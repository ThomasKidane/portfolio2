# Direct preference optimization

## Historical question and bottleneck

[Direct Preference Optimization: Your Language Model is Secretly a Reward Model](https://arxiv.org/abs/2305.18290) (Rafailov et al., 2023) is the primary reference. The original question motivating this module is how to implement reference-relative chosen-rejected log-probability margins on licensed preferences. The practical bottleneck for this exercise is explicit: Prompt tokens masked; frozen reference never updated. This is a reduced teaching adaptation, not a claim that the paper used our dataset or compute budget.

## Mechanism and equations

$$
\begin{aligned}
L_{\mathrm{DPO}}=-\mathbb E\log\sigma\!\left(\beta\left[\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}\right]\right)
\end{aligned}
$$

Here x is a prompt, y-w/y-l preferred/rejected completions, pi-theta the trained policy, pi-ref a frozen reference, beta positive preference scale, and sigma sigmoid. Sequence log probabilities sum completion-token log probabilities under the same conditioning.

Derive each tensor's dimensions before implementing the equation. State the normalization axis, numerical stabilizer and train/evaluation behavior. Distinguish a mathematical mechanism from the full original training system.

## Implementation notes

Input/task: **licensed-preference-pairs**. Output: **Prompt completion -> summed completion log probability**. Optimize or report **preference_accuracy** in the **maximize** direction. Prompt tokens masked; frozen reference never updated.

This is a draft skeleton: reference training and task-specific tests are not implemented. The explicit stub must not be mistaken for a finished model.

## Controlled experiment

Remove reference-model correction and inspect held-out preference accuracy. Keep split, seed, optimizer schedule and training budget fixed unless that factor is the experimental variable. Report raw quality, wall time and parameter count, not an unsupported superiority claim.

## Pitfalls and checks

- Prompt tokens masked; frozen reference never updated.
- Never fit statistics on validation labels or mix held-out examples into training.
- Check shape and finite outputs before interpreting quality; an unrelated baseline cannot satisfy the intended mechanism.
- Draft targets and safety limits have not been GPU-calibrated. No pass threshold is advertised.
