# Compute-optimal language modeling: derivation and implementation notes

## The mechanism

$$
\begin{aligned}
C\approx\kappa ND,\\ (N^*,D^*)=\arg\min_{N,D>0}\left[L_\infty+AN^{-\alpha}+BD^{-\beta}\right]\quad\text{subject to }\kappa ND\le C_0
\end{aligned}
$$

Here N is parameters, D training tokens, kappa an architecture-dependent compute factor, C-zero a fixed budget, and the other constants fit loss observations. This approximate training-compute model does not replace measured hardware time or prescribe universal optimal counts.

## A reproducible approach

1. State the model's input/output shapes and the loss before coding.
2. Set a seed, use only the supplied training split, and keep preprocessing statistics training-only.
3. Validate the local contract before comparing held-out metrics. A contract check is not an accuracy grade.
4. Run the ablation with identical splits and compute budget; save your observations outside the shared site.

## Task-specific evaluation

Dataset: **measured-training-runs**. Model contract: **Compute allocation -> fitted loss frontier**. Metric: **heldout_loss**, direction **minimize**. Compare allocations at equal measured training FLOPs.

No calibrated passing threshold is available.



## Required ablation

Compare equal-parameter with equal-compute allocations. Keep the seed, split, training steps and optimizer fixed. Report both quality and compute cost; one run is not statistical evidence.

## Failure modes

- Fitting on validation labels or allowing split overlap invalidates evaluation.
- Matching output shape alone does not establish that the intended mechanism was implemented.
- A small teaching model is not the original full-scale experiment.
